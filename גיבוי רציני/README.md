# גיבוי רציני

גיבוי אוטומטי של המאגר `kvutzat-rechisha`.

## איך זה עובד

| מה | איפה | מתי |
|---|---|---|
| גיבוי בענן | לשונית **Releases** במאגר ב-GitHub, תגיות `backup-תאריך` | כל לילה ב-03:17 בערך, אוטומטית |
| גיבוי במחשב (רשות) | `Documents\גיבוי רציני` במחשב שלך | לפי תזמון שתגדיר (ראה למטה) |

כל גיבוי בענן כולל:
- **`.bundle`** – כל הענפים, כל התגיות וכל ההיסטוריה. זה הגיבוי המלא.
- **`.zip`** – הקוד העדכני מהענף הראשי, לפתיחה מהירה.
- **`checksums.txt`** – לבדיקה שהקבצים תקינים.

נשמרים 30 הגיבויים האחרונים; הישנים יותר נמחקים אוטומטית.
ההגדרה נמצאת בקובץ `.github/workflows/backup.yml` (GitHub מחייב שהקובץ יהיה שם).

### הפעלה ידנית
GitHub ← המאגר ← **Actions** ← "גיבוי רציני" ← **Run workflow**.

## מה *לא* נכלל
קבצים שמופיעים ב-`.gitignore` אינם ב-GitHub ולכן אינם בגיבוי:
קובצי `.env` (מפתחות וסיסמאות), התיקיות `סודי` ו-`שמות והזמנות הלקוחות`, קובצי `xlsx`/`sql`/`py`.
**אותם יש לגבות בנפרד** (למשל לכונן חיצוני או לענן פרטי).
גם נתוני מסד הנתונים עצמו וההגדרות ב-Vercel אינם חלק מהמאגר.

## שחזור
```bash
git clone kvutzat-rechisha_<תאריך>.bundle kvutzat-rechisha
```
מתקבלת תיקייה מלאה עם כל ההיסטוריה. לשחזור כל הענפים:
```bash
git clone --mirror kvutzat-rechisha_<תאריך>.bundle repo.git
```

## גיבוי נוסף למחשב (מומלץ)
הגיבוי בענן נשמר ב-GitHub עצמו. כדי שיהיה עותק גם אם תהיה בעיה בחשבון,
הפעל במחשב Windows את `גיבוי-למחשב.ps1` (דורש Git מותקן).
הוראות לתזמון יומי אוטומטי כתובות בראש הקובץ.
